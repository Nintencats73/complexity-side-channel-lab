How does work scale?

Choose a growth function and change the input size. The graph compares estimated operation counts—not elapsed seconds.

Read the graph: Big-O describes how resource use grows as n becomes large. It suppresses constant factors and lower-order terms; it is not a precise runtime prediction for a particular computer.

Examples: scanning an unsorted list is typically O(n); checking every pair is O(n²); binary search on sorted data is O(log n); and a typical comparison sort is O(n log n).

Can elapsed time reveal a secret?

Important: the “time units” are a simplified teaching model, not measurements from your device. Real timing depends on noise, hardware, runtime, network conditions, and many other factors. Do not use this demo to test real systems or secrets.

Why it matters: if response time depends on how many leading characters match, repeated measurements may leak information about a secret. A fixed-work comparison aims to avoid data-dependent early exits. Real constant-time engineering requires careful implementation and platform-aware testing; source-code appearance alone is not proof.
